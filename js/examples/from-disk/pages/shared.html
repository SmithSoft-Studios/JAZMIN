One file, three people

The same shared.jzm, one copy, opened with three access keys. Each key unlocks only what its grant allows: its branches' rows, the pay columns or not, and the files, saved shapes and document pages of the groups it sees. What a key can't see isn't hidden by the page: it can't be decrypted at all. HR also has a locked file: its key sees it, but opening it takes a password too.

What this shows

One file opened with three access keys, side by side: each card shows only the rows, columns, saved shapes, files and document tabs its key can decrypt. HR's key adds a Pay review tab, marked on a file of the hr group, and sees a file locked with a password, which it can unlock here or in the viewer; the other keys see neither the tab nor the file's name.

Feature: access control, pages only some keys see, locked files · USER-GUIDE §15, §19.7 and §19.6

Open it three times

The three keys are in data/shared-keys.js for this demo only. A real key is like a password: it never belongs in a page.

How the file was written

write('shared.jzm', staff, { columns, key: ownerKey,
  access: {
    partitionBy: 'branch',                         // rows, by branch
    columnGroups: { pay: ['salary', 'bonus'] },    // columns, by group
    grants: [
      { key: capeTownManager, rows: ['Cape Town'], columns: '*' },
      { key: johannesburgLead, rows: ['Johannesburg'], columns: ['*'] },  // '*' alone: no pay
      { key: hr, rows: '*', columns: '*', files: ['hr'] },
    ],
  },
  files: [
    { path: 'handbook.html', content },                              // everyone's
    { path: 'hr/pay-review.html', file, groups: ['hr'],
      page: { title: 'Pay review 2027', order: 1 } },               // a tab only HR's key knows of
    { path: 'hr/increases-2027.csv', content, groups: ['hr'], lock: 'pay-review' },
    …],
  locks: { 'pay-review': { password: 'review 2027' } },              // a password as well as the key
  package: { pages: [{ path: 'handbook.html', title: 'Handbook' }] },
  shapes: [{ name: 'Pay by branch', groups: ['hr'], shape }, …],  // only for keys that see pay
});

// In a page: the locked file is listed, but reading it needs the lock opened first.
(await reader.files()).find((f) => f.lock);      // { path, …, lock: { id: 'pay-review', kind: 'password', unlocked: false } }
await reader.unlock('pay-review', { password }); // a wrong one throws JazminKeyError

The package settings (pages) are in the file's header, which every key reads, so only the Handbook is listed there. HR's page is marked on its own file instead, in the hr group's directory, which only keys that see that group can decrypt.

A shape that uses salary, saved for a group whose keys can't all see that column, is refused when the file is written, naming the key. So each list above is exactly what its key can use.
