One file, three people

The same shared.jzm, one copy, opened with three access keys. Each key unlocks only what its grant allows: its branches' rows, the pay columns or not, and the files and saved shapes of the groups it sees. What a key can't see isn't hidden by the page: it can't be decrypted at all.

Open it three times

The three keys are in data/shared-keys.js for this demo only. A real key is like a password: it never belongs in a page.

How the file was written

write('shared.jzm', staff, { columns, key: ownerKey,
  access: {
    partitionBy: 'branch',                         // rows, by branch
    columnGroups: { pay: ['salary', 'bonus'] },    // columns, by group
    grants: [
      { key: capeTownManager, rows: ['Cape Town'], columns: '*' },
      { key: johannesburgLead, rows: ['Johannesburg'], columns: ['*'] },  // '*' alone: no pay
      { key: hr, rows: '*', columns: '*', files: ['hr'] },
    ],
  },
  files: [{ path: 'hr/pay-bands.html', content, groups: ['hr'] }, …],
  shapes: [{ name: 'Pay by branch', groups: ['hr'], shape }, …],  // only for keys that see pay
});

A shape that uses salary, saved for a group whose keys can't all see that column, is refused when the file is written, naming the key. So each list above is exactly what its key can use.
