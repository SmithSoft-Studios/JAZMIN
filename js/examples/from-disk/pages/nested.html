Nested columns: orders with their lines

A home-and-hardware store's 5,000 online orders. Each order's lines (product, quantity, price) are a list of objects, and its delivery an object, stored as columns are: numbers as numbers, repeated text once per chunk. A filter reaches inside them, and the file is smaller than the same orders with those two as JSON text.

What this shows

The same orders in two files: lines and delivery as nested columns, and as JSON text. Filters with any, all and match look inside the nested ones, decoding only the fields they need; the JSON file has to be read and parsed row by row to answer the same question.

Feature: nested columns, filters any / all / match · USER-GUIDE §4.2 and §8.1

How the files were written

write('orders.jzm', orders, { sortedBy: ['date'], columns: [
  { name: 'order', type: 'string' }, { name: 'date', type: 'datetime' }, { name: 'customer', type: 'string' },
  { name: 'branch', type: 'string', index: 'sorted' },
  { name: 'delivery', type: 'object', fields: [{ name: 'method', type: 'string' }, { name: 'city', type: 'string' }] },
  { name: 'lines', type: 'list', item: { type: 'object', fields: [
    { name: 'sku', type: 'string' }, { name: 'product', type: 'string' }, { name: 'qty', type: 'int' }, { name: 'price', type: 'decimal' },
  ] } },
  { name: 'total', type: 'decimal' },
] });
// orders-json.jzm: the same, with { name: 'lines', type: 'json' } and { name: 'delivery', type: 'json' }

Nested columns can't be indexed or sorted by; files keep min/max statistics of their fields, so any and match skip chunks where no item can match. Files with nested columns need JAZMIN 1.4 or later; earlier versions refuse them, never misread them.
