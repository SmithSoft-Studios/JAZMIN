Text orders: A2 before A10, and du Plessis with the Ds

A wholesaler's customers, written twice. Plain order compares text character by character: capitals before small letters, accented letters after z, and Bakery 21 before Bakery 7. The other copy is kept in an order that ignores case and accents and puts the numbers in names by value, as people expect a list to read.

What this shows

The same 44 customers in two files: one sorted by name as plain text, one by { column: 'name', nocase: true, natural: true }. Rows come back in the file's order, so a search, a page of rows and a read last first (reverse: true) all follow it, with no sort in the page.

Feature: other text orders (nocase, natural) · USER-GUIDE §16.1 (spec 6.7)

Plain order

sortedBy: ['name'] ·

    Ignoring case and accents, numbers by value

    sortedBy: [{ column: 'name', nocase: true, natural: true }] ·

      Marked names start with a small or accented letter, or have a number in them: the ones plain order puts somewhere a person wouldn't look.

      How the files were written

      // Written in the order the customers signed up, then put in order (a write takes rows already in order):
write('customers.jzm', rows, { columns });
update('customers.jzm', { sortedBy: [{ column: 'name', nocase: true, natural: true }] });

// Reading: the rows come in that order; the reader says which order it is.
reader.sort;       // [{ column: 'name', nocase: true, natural: true }]
reader.sortedBy;   // undefined: only the plain leading keys of the order, which every reader relies on
reader.query({ name: { icontains: 'bakery' } });   // Bakery 7, Bakery 21

      Filters still compare values exactly. Releases 1.0 to 1.6 read such a file correctly, with only the plain part of its order; if they append to it, they drop the rest of the order.
